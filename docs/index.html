01 / 产品概述

它是什么

WorkBuddy 加油站每日签到是一个运行在本机的命令行工具。它把「打开客户端、进入加油站、点击签到」这组动作，收敛为一条命令或一个定时任务。

1

谁需要它

每天使用 WorkBuddy，但经常忘记签到，或希望把签到接入自动化任务的用户。

2

解决什么问题

手动签到易遗漏；单次定时触发可能延后；平台只展示连续天数，缺少每日明细。

3

边界在哪里

不代登录、不刷新令牌、不改写客户端文件，仅调用官方签到接口。

02 / 功能特性

做得少，但每件都做对

签到链路本身不复杂。工程难点在于凭据安全、重复提交、定时漏跑与结果可追溯。

签

签到与复查

先查询状态，未签到则领取，领取后再查一次，确认积分实际到账。

幂

幂等跳过

当天台账已有成功记录时直接跳过，不发起任何网络请求，多次触发也不重复提交。

锁

并发保护

进程锁阻止多个定时任务同时领取；超过 10 分钟的陈旧锁自动回收。

重

失败重试

网络异常、5xx、429 按指数退避重试。领取接口不重试 5xx，避免响应丢失后的重复提交。

诊

离线自检

--doctor 检查客户端路径、登录态、密钥链与令牌可解性，全程不联网。

账

台账与清洗

--history 输出每日结果与疑似漏签日期；--redact-history 清洗历史个人信息并自动备份。

03 / 工作原理

五步完成一次签到

客户端把落盘的敏感字段做了字段级加密，因此工具需要先取密钥，再解封访问令牌。令牌只在内存中流转。

取密钥

同进程绑定 → 客户端子进程 → 用户自备，按序尝试。

解封令牌

AES-256-GCM 解封登录态字段，明文不落盘。

查状态

查询今日是否已签到，读取连续天数与累计积分。

领取积分

未签到时调用领取接口，随后复查一次。

写台账

按字段白名单写入，输出结构化结果。

动作方法路径
查询签到状态POST/v2/billing/meter/checkin-activity-status
领取每日积分POST/v2/billing/meter/daily-checkin
04 / 快速开始

三条命令跑起来

无需安装依赖。确认本机已安装 WorkBuddy 桌面端并登录过一次。

# 1. 获取代码
git clone https://github.com/Eleven1111/workbuddy-daily-checkin.git
cd workbuddy-daily-checkin

# 2. 离线自检（不联网）
node src/checkin.mjs --doctor

# 3. 签到
node src/checkin.mjs --json

配置定时任务

一天触发三次，配合 --if-needed 保证不漏签，也不重复请求。

0 6,12,22 * * * /usr/bin/node /绝对路径/src/checkin.mjs --if-needed --quiet
命令用途
--check-only只查询状态，不领取
--if-needed当天已成功则跳过，不发起网络请求
--doctor离线自检本机环境
--history=30近 30 天台账与漏签检测
--redact-history清洗历史台账中的个人信息
--json输出固定字段，便于自动化任务消费
05 / 安全说明

凭据不进仓库，也不进日志

默认脱敏。台账只写入白名单字段：签到结果、积分、连续天数、HTTP 状态与一行结论。账号昵称、密钥标识、令牌长度、令牌有效期与原始响应一律不落盘，文件权限为 0600。
  • 源码不含任何编译期密钥或真实凭据，密钥在运行时按链路获取。
  • --verbose 的调试信息只写入标准输出，不写入台账。
  • 登录态过期时直接退出并提示重新登录，不刷新、不改写凭据。
  • 仓库内置防泄露扫描，CI 校验疑似密钥与手机号。
  • 仅用于本人设备、本人账号；使用前请确认符合平台服务条款。
06 / 常见问题

排错入口

提示「无法取得 at-rest 密钥」

客户端未安装、未登录，或运行环境没有原生模块。确认客户端已登录；或通过 WB_ATREST_SECRET_B64、WB_SECRET_FILE 自备密钥。

提示「无法解出登录令牌」或自检显示 MISMATCH

客户端升级后更换了加密方案或密钥。打开客户端登录一次，再执行 --doctor 确认。

提示「登录态已过期」或返回 401

会话已失效。打开客户端重新登录即可，本工具不会自行刷新令牌。

输出「今日已签到，跳过本次请求」

--if-needed 生效，属正常结果。如需强制请求，添加 --force。

读取登录态时报 EPERM

命令被运行环境的沙箱拦截。以无沙箱方式重试一次。
